AI Chatbot Builder

A no-code platform where anyone can create a custom AI chatbot trained on their own documents and embed it on any website — no technical knowledge required.

OpenAI + RAG React + Node.js Vector Database High Upwork Demand

🤖 What It Does

Users sign up, upload their documents (PDFs, text files, Word docs), and the app creates a chatbot that can answer questions based on that content. The chatbot gets a shareable link and an embeddable widget they can drop into any website with one line of code.

📄
Document Upload
Upload PDFs, TXT, or DOCX files. The system chunks, embeds, and indexes them automatically.
🤖
Custom Chatbot
Name your bot, set its personality and welcome message. It answers questions using only your documents.
💬
Live Chat Interface
A clean chat UI for testing and using the bot directly in the dashboard.
🔗
Embeddable Widget
One script tag to embed the chatbot on any website as a floating bubble or inline widget.
📊
Usage Dashboard
See total messages, active chatbots, documents uploaded, and recent conversations.
🔐
Auth + Multi-bot
Each user can create and manage multiple chatbots. Full register/login flow.
💡Why this is valuable on Upwork: Businesses constantly need custom chatbots for their FAQs, docs, and support. Knowing how to build the RAG pipeline (embeddings + vector search + OpenAI) is one of the highest-paid skills right now at $50–100/hr.

⚙️ The RAG Pipeline

RAG stands for Retrieval-Augmented Generation. Instead of fine-tuning a model (expensive, slow), you retrieve relevant chunks of the user's documents at query time and feed them as context to GPT. This is the core of the entire app.

Key Concepts

Chunking

You can't send an entire 50-page PDF to GPT — it's too many tokens and costs too much. Instead you split the document into overlapping chunks of ~500 tokens each. Overlap (e.g. 50 tokens) ensures you don't lose context at chunk boundaries.

// Simple chunking with overlap
function chunkText(text, chunkSize = 500, overlap = 50) {
  const words = text.split(' ');
  const chunks = [];
  for (let i = 0; i < words.length; i += chunkSize - overlap) {
    chunks.push(words.slice(i, i + chunkSize).join(' '));
    if (i + chunkSize >= words.length) break;
  }
  return chunks;
}

Embeddings

An embedding is a list of numbers (a vector) that represents the meaning of a piece of text. Two pieces of text with similar meanings will have vectors that are mathematically close to each other. This is how you do semantic search — "refund" will match "money back guarantee" even though the words are different.

The System Prompt

This is the most important part of the chat quality. Build it like this:

const systemPrompt = `You are ${chatbot.name}, a helpful assistant for ${chatbot.companyName}.
Answer questions based ONLY on the context provided below.
If the answer is not in the context, say "I don't have information about that."
Be concise, friendly, and accurate.

Context:
${retrievedChunks.join('\n\n')}
`;
⚠️Important: Always tell GPT to answer ONLY from the provided context. Without this, it will hallucinate answers from its training data, which is not what you want for a business chatbot.

🗄️ Database Schema

// schema.prisma

model User {
  id        String     @id @default(cuid())
  email     String     @unique
  password  String     // bcrypt hash
  name      String?
  createdAt DateTime   @default(now())
  chatbots  Chatbot[]
}

model Chatbot {
  id             String     @id @default(cuid())
  userId         String
  user           User       @relation(fields: [userId], references: [id])
  name           String
  description    String?
  welcomeMessage String     @default("Hi! How can I help you?")
  accentColor    String     @default("#6366f1")
  createdAt      DateTime   @default(now())
  documents      Document[]
  conversations  Conversation[]
}

model Document {
  id         String   @id @default(cuid())
  chatbotId  String
  chatbot    Chatbot  @relation(fields: [chatbotId], references: [id], onDelete: Cascade)
  filename   String
  fileType   String   // "pdf" | "txt" | "docx"
  chunkCount Int
  createdAt  DateTime @default(now())
  chunks     Chunk[]
}

model Chunk {
  id         String   @id @default(cuid())
  documentId String
  document   Document @relation(fields: [documentId], references: [id], onDelete: Cascade)
  content    String   // the raw text of this chunk
  embedding  Float[]  // pgvector column — 1536 dimensions for text-embedding-3-small
  chunkIndex Int
}

model Conversation {
  id        String    @id @default(cuid())
  chatbotId String
  chatbot   Chatbot   @relation(fields: [chatbotId], references: [id])
  createdAt DateTime  @default(now())
  messages  Message[]
}

model Message {
  id             String       @id @default(cuid())
  conversationId String
  conversation   Conversation @relation(fields: [conversationId], references: [id])
  role           String       // "user" | "assistant"
  content        String
  createdAt      DateTime     @default(now())
}
ℹ️The embedding Float[] column uses Supabase's pgvector extension. You need to enable it in Supabase with: CREATE EXTENSION IF NOT EXISTS vector; and then alter the column type to vector(1536) via a raw SQL migration.

🏗️ Build Order

Follow this sequence — each step builds on the last. Don't jump ahead.

  1. 1
    Project setup
    Create Vite React app + Express server in a monorepo. Set up Supabase project, enable pgvector extension, connect Prisma. Configure .env with DB URL + OpenAI API key.
  2. 2
    Auth — register + login
    User model in Prisma. POST /register hashes password with bcrypt. POST /login returns JWT. JWT middleware to protect routes. Frontend: Login + Register pages.
  3. 3
    Chatbot CRUD
    Create/list/delete chatbots. Dashboard page listing all the user's bots. "New chatbot" modal form.
  4. 4
    File upload + text extraction
    multer middleware for file upload. Use pdf-parse for PDFs and mammoth for DOCX. Return raw text string from each file type.
  5. 5
    Chunking + embedding pipeline
    Split extracted text into 500-token chunks with 50-token overlap. Call OpenAI text-embedding-3-small for each chunk. Batch these calls — don't call one by one. Save chunks + embeddings to Supabase pgvector.
  6. 6
    Chat endpoint (the core feature)
    Embed the incoming user message. Run vector similarity search in pgvector to retrieve top 5 relevant chunks. Build the system prompt with those chunks as context. Call gpt-4o-mini. Return the response.
  7. 7
    Chat UI in dashboard
    A clean chat interface inside the dashboard for testing the bot. Shows messages in a scrollable list, input at the bottom, loading state while GPT responds.
  8. 8
    Public chat page
    A standalone page at /chat/:botId — no login required. Anyone with the link can chat with the bot. This is what gets embedded in the widget.
  9. 9
    Embed widget
    A small vanilla JS file (widget.js) hosted on your server. When loaded on a third-party site, it injects a floating chat bubble. On click, opens an iframe pointing to /chat/:botId. User copies a single script tag from the dashboard to embed it.
  10. 10
    Streaming responses (Phase 2)
    Switch gpt-4o-mini call to stream: true. Use Server-Sent Events (SSE) or chunked transfer to stream tokens to the frontend. React renders each token as it arrives — much better UX.

🤖 AI Prompts to Use With Claude Code

Supabase pgvector setup

"I'm using Prisma with Supabase PostgreSQL. How do I enable pgvector and store embeddings as a vector(1536) column in my Chunk model? Show me the raw SQL migration and the Prisma schema setup."

Document ingestion pipeline

"Write a Node.js function called ingestDocument(file, chatbotId) that: (1) extracts text from a PDF using pdf-parse or DOCX using mammoth, (2) splits the text into chunks of ~500 words with 50-word overlap, (3) calls OpenAI text-embedding-3-small to embed each chunk in batches of 20, (4) saves each chunk with its embedding to Supabase pgvector using Prisma."

Chat endpoint with RAG

"Write an Express POST /api/chatbots/:id/chat endpoint that: (1) embeds the incoming user message using OpenAI text-embedding-3-small, (2) runs a pgvector similarity search to get the top 5 most relevant chunks for this chatbot, (3) builds a system prompt with those chunks as context, (4) calls gpt-4o-mini with the conversation history, (5) saves the user message and assistant response to the Conversation/Message models, and (6) returns the response."

Embed widget

"Write a vanilla JS embed widget (no frameworks) that website owners can drop in with a single script tag. It should inject a floating chat bubble in the bottom-right corner. When clicked, it opens an iframe pointing to https://myapp.com/chat/CHATBOT_ID. The script tag should look like: <script src='https://myapp.com/widget.js' data-chatbot-id='abc123'></script>"

Streaming response with SSE

"Convert my existing chat endpoint to stream the OpenAI response using Server-Sent Events (SSE). Show me both the Express backend changes (stream: true, res.write for each chunk) and the React frontend changes (reading the SSE stream and appending tokens to the message in state)."

pgvector similarity search

"Write a raw SQL query using Supabase pgvector that finds the 5 most similar chunks to a given query embedding vector, filtered by chatbotId. Use the cosine distance operator (<=>). Show me how to run this with Prisma's $queryRaw."

File upload with multer

"Set up multer in Express to handle single file uploads. Accept only PDF, TXT, and DOCX files (reject others with a 400 error). Store the file in memory (not disk) using memoryStorage so I can process it directly without saving to the filesystem."
